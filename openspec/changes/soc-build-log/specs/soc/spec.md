# Spec Delta

## MODIFIED Requirements

### Requirement: Отчёт сборки называет генератор top.v
Имя верхнего модуля MUST быть свойством `project.top` дизайна. `FSOC_SOC_TOP` MUST задавать каталог, а имя файла MUST быть `<каталог>/<project.top>.v`. Успешный `fsoc --build` в `projects/soc_emul` MUST напечатать выходной файл фрагмента топа строкой `fhdlgen: <имя>` из пути, уже записанного в этот фрагмент. Отдельной подписи с литералом `top.v` в `fsoc` MUST NOT быть. И MUST напечатать, сколько байт из 8192 занял словарь ядра и чему равен указатель кода. Предупреждения Gforth MUST остаться на экране. Строка `tdp` MUST NOT склеиваться с текстом предупреждения.

#### Scenario: Две строки вместо emit ok и tdp
- **WHEN** сборка ядра проходит успешно
- **THEN** в выводе есть `fhdlgen: top.v` и строка `SwapForth nucleus: dictionary at $` с байтами из 8192 и указателем кода, а в `fsoc/soc.4th` нет литерала `fhdlgen: top.v`

## ADDED Requirements

### Requirement: Список Verilog берётся из фрагмента топа
После разбора топа fhdlgen хранит каждый `hdl-include-v` элементом фрагмента этого топа с видом include-verilog и путём файла. fhdlgen MUST сам напечатать каждый такой путь строкой `fhdlgen: <путь>`. Список в `fsoc` MUST NOT передаваться. Обход каталога проекта и отдельная литеральная строка с несколькими именами `*.v` MUST NOT быть источником. Файл, скопированный в каталог проекта, но не записанный include-verilog в топе, в этой секции MUST NOT появляться. `top.v` по-прежнему называет шаг генерации.

#### Scenario: В логе листы топа
- **WHEN** `fsoc --build` разбирает `designs/soc_top.4th`
- **THEN** секция Hardware содержит отдельной строкой каждый путь, который этот топ передал в `hdl-include-v`, и не содержит `tb_timer.v` и `tb_regio.v`

#### Scenario: В одной строке нет списка модулей
- **WHEN** смотрят исходник отчёта сборки SoC
- **THEN** нет строки, в которой записаны два или больше имени `*.v`

### Requirement: Литерал не заменяет неизвестный источник
Имя или список, который сборка показывает или использует, MUST браться из данных проекта: копируемый файл, генерация, кросс-компиляция, подача в образ. Если такого источника нет, литеральный список MUST NOT записываться ни в отчёт, ни в код сборки. Реализация MUST остановиться и спросить, откуда брать данные и как их использовать.

#### Scenario: Нет источника — нет выдуманного списка
- **WHEN** для строки отчёта не найден шаг проекта, который уже несёт это имя
- **THEN** в коде нет литерала с этим списком, и строка в лог не попадает
