# Design

## Context

См. proposal.md — Why. `soc-cp` уже получает имя файла и копирует его. Строка `verilog: stack2.v j1.v …` в `soc-emit-emulation` этот аргумент не читает. `soc-cross` и `soc-feed-file` тоже уже знают путь исходника и печатают его второй, отдельной строкой.

## Goals / Non-Goals

**Goals:**

- Одно имя на строку, взятое из аргумента того шага, который файл копирует, генерирует, компилирует или подаёт.

**Non-Goals:**

- Не заводить второй массив имён «для лога».
- Не менять, какие файлы копируются.
- Не подставлять литерал, если шаг проекта с этим именем не найден. В этом случае остановиться и спросить, откуда брать данные.

## Decisions

- Список листов — элементы `frag/include-verilog` фрагмента топа. fhdlgen при выпуске этого фрагмента печатает `fhdlgen: <путь>` на stdout. В `fsoc` список не передаётся и не печатается. stdout fhdlgen не уводится в файл, иначе строки не видны в логе сборки.
- `tb_timer.v` и `tb_regio.v` копируются в проект, но в топе их нет, поэтому в секции Hardware их нет.
- Имя верхнего модуля — свойство `project.top` в дизайне (`s" top" project.top!`). `FSOC_SOC_TOP` и `FSOC_BLINKY_TOP` задают только каталог. Имя файла — `project.out-path`: `<каталог>/<project.top>.v`. Модуль в `hdl-module`, `--top-module` и Quartus читают то же свойство. fhdlgen пишет его в `<каталог>/top-module` и печатает имя выходного файла из `file-frag.path`. В `soc-gen-top` нет второй строки с именем `top.v`. `project.name` остаётся именем проекта, не модуля.
- `soc-cross` печатает путь, который уже подставляет в команду `gforth`. `soc-feed-file` печатает путь, который уже подставляет в `FSOC_EMU_FEED`. Отдельные `." firmware: …"` перед вызовом убираются.
- Заголовки `fsoc: <проект> - Hardware` и `Software` остаются. Они не называют файлы. Звёздочки в префиксе нет.

## Risks / Trade-offs

- [Новый `hdl-include-v` в топе] → он уже попадает в список фрагмента, отдельная правка лога не нужна.
