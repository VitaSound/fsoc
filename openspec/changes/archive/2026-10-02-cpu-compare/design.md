# Design

## Context

Пользователь выбрал сравнение по тактам Verilator и размеру образа. Площадь и Fmax отложены до второго ядра, которое уже синтезируется. J1B — 32-битная клетка при той же модели исполнения, что J1a.

## Goals / Non-Goals

**Goals:**

- Один сценарий, одна плата или эмуляция без смены тулчейна между строками, несколько `cpu:`.
- Столбцы: id профиля, MM, EX-C, CG, ширина клетки, байты образа, такты.
- Победитель по тактам только среди строк с одинаковыми MM, EX-C и CG и с заполненной колонкой тактов.

**Non-Goals:**

- LUT, триггеры, блочная память, Fmax, размер битстрима.
- Одно взвешенное число.
- Синтез.

## Decisions

1. Сценарий консоли — строка `1 2 + .` до ответа, содержащего `3` и ` ok`. Сценарий лампы — один период смены `IO-LED`. В одном отчёте один сценарий.
2. Байты образа печатаются рядом с шириной клетки. Меньший hex при другой ширине клетки победителем по размеру не считается.
3. Строка без обёртки (j1b до появления WIDTH 32) входит в отчёт с пустыми тактами и не участвует в сравнении «меньше тактов».
4. Смешение `quartus` и `yosys` в одном отчёте не является сравнением ядер. Инструмент такой отчёт не помечает как сравнение.
5. Инструмент — слово или скрипт в fsoc, который гоняет уже собранную эмуляцию и читает счётчик тактов. Реализация этого слова не входит в запись спеки; задачи ниже описывают её.

## Risks / Trade-offs

- Пока обёртки j1b нет, отчёт содержит одну живую строку тактов. Это честно и не изображает победителя.
