# Proposal

## Why

`fsoc/soc_main.cpp` (390 строк) — одновременно симулятор, UART-кодек, терминал, вторая стадия кросс-компилятора (`FSOC_EMU_FEED`, раскрытие `include` SwapForth, снимок RAM) и тестовый оракул (ищет `lamp on` / `lamp off`, считает переключения `led`). Он знает текст прошивки, фазы рукопожатия SwapForth и имя `top__DOT__u__DOT__ram` из иерархии дизайна. `blinky_main.cpp` повторяет цикл тактов, SIGINT, `env_int` и realtime-паузу. Делитель UART `kBit=104` жёсткий и не соответствует такту 50 МГц, что помешает выходу на плату.

## What Changes

- `emu/` становится библиотекой: `clock` (цикл тактов, SIGINT, realtime-пауза, `cycle_cap`, чтение `FSOC_EMU_*`), `uart` (приём и передача 8N1 с делителем-параметром), `script` (подача строк из `FSOC_EMU_UART_IN` / stdin / панели, ожидание ` ok` и `?`). `con` остаётся.
- `main` задач становится тонким: blinky — такт, `con_pin`, предел `FSOC_EMU_EDGES`; soc — такт, UART, скрипт, панель.
- Оракулы уходят из `main`: нет поиска `lamp on` / `lamp off`, нет счётчика переключений. Тесты проверяют журнал. `FSOC_EMU_FAST=1` без скрипта ограничивается `FSOC_EMU_CYCLES`.
- Стадия прошивки — отдельный исполняемый файл `soc_feed` с контрактом «выполнить исходник, снять RAM»: читает уже плоский файл (без `include`), снимок пишет сам `j1_wrap.v` по входу `dump` через `$writememh`. Раскрытие `include` SwapForth делает Forth в билдере.
- Делитель UART — параметр `CLK_HZ` / `BAUD` обёртки и тот же делитель в `emu/uart`; источник значения — один (позже `iomap` / плата).
- Коды выхода: 0 — сценарий выполнен или предел достигнут; 1 — сценарий не завершён; 130 — Ctrl+C.
- **BREAKING**: `FSOC_EMU_SNAPSHOT` исчезает (снимок — контракт `soc_feed`); `FSOC_EMU_FAST=1` на `soc_blink` без `FSOC_EMU_CYCLES` больше не завершает прогон сам.

## Capabilities

### New Capabilities

- `emulation`: библиотека эмуляции — такт, UART-кодек, скрипт сеанса, коды выхода, отдельный шаг прошивки.

### Modified Capabilities

- `console`: без изменения требований к печати; добавляется требование, что `con` не знает прошивку и дизайн (нет литералов текста прошивки, нет иерархических имён).
- `soc`: «Запуск сеанса» — коды выхода и завершение без оракула; новое требование «Образ прошивки собирает отдельный шаг».
- `blinky`: «Эмуляция не знает задачу» — `main` берёт такт и события из библиотеки `emu/`, каталог `emu/` содержит библиотеку, а не только консоль.

## Impact

- `emu/con.*` без изменений; новые `emu/clock.*`, `emu/uart.*`, `emu/script.*`; `fsoc/tasks/blinky_main.cpp`, `fsoc/tasks/soc_main.cpp`, `fsoc/tasks/soc_feed.cpp`; `cpu/j1/j1_wrap.v` (порт `dump`, параметры делителя); `targets/emulation.4th` (`sim.sh` собирает `*.cc` из `emu/` и два `main`); `fsoc/tasks/soc.4th` (плоский feed-файл, вызов `soc_feed`); тесты `soc_test`, `soc_blink_test`, `blinky_test`.
