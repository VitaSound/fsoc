# Design

## Context

См. proposal.md — Why. Сейчас `soc-swap` в `fsoc/tasks/soc.4th` склеивает префикс `cpu/j1/swapforth/`, а `soc-cg-i` сам вызывает `soc-cross` и подачу. Комплект называет порт строкой `s" j1a" kit-cross` в `cpu/j1/j1a/kit.4th` (и так же `j1b`). Поле `cpu:` уже выбирает профиль. Поля `sys:` нет.

Спецификация `soc` требует, чтобы всякий образ был SwapForth с полным ANS CORE. Для пустого `sys:` это остаётся. Образ fsys этим списком не меряется: его поведение задаёт спецификация `fsys`.

## Goals / Non-Goals

**Goals:**

- Два инструмента образа на одном `cpu:` и одном чипе. Задача вызывает один шаг выбранного инструмента.
- fasm на хосте пишет те же 16-битные команды, что поля SwapForth, строками `$readmemh`. j1b упаковывает две команды в слово.
- kernel и common дают сессию `words` и `1 2 + .`, затем переменную и деление.
- Порог `fcov` 90% на каждый каталог слоя отдельно.

**Non-Goals:**

- Ассемблер stm8 и z80. Каталоги `fsys/fasm/stm8/` и `fsys/fasm/z80/` остаются пустыми слотами. CG=E и CG=F по-прежнему останавливают сборку до образа.
- Копия `nuc.fs`, `basewords.fs` или `core.fs` в дерево fsys. Общих файлов с `swapforth/` нет.
- Исходники и лицензия fasm-mc14500. Берётся только приём: слово с запятой и сессия `[asm]` … `[endasm]`.
- Полный ANS CORE в fsys. Четвёртый слой. Имена `upper`, `nuc`, `core` для каталогов fsys.
- Запись `cpu: j1b` в `projects/soc_emul/target.4th`.

## Decisions

### Поле sys рядом с cpu

`sys:` живёт в ядре билдера, как `cpu:` и `task:`. Пустая строка в манифесте читается как `swapforth` в одном месте, до выбора шага. Задача `soc` получает уже выбранный id и вызывает зарегистрированный шаг этого id. Сравнение со строками `swapforth` и `fsys` стоит в регистрации инструментов, не в `soc-cg-i`.

Альтернатива — переиспользовать `target:`. Отклонено: `target:` уже означает emulation, quartus, yosys.

### Монолит SwapForth переносится целиком

`git` переносит `cpu/j1/swapforth` в `swapforth/` без разрезания `cross.fs`, `basewords.fs`, `nuc.fs`, `swapforth.fs` и `common/`. Префикс `soc-swap` меняется на `swapforth/`. `kit-cross` и поле `kit.cross$` удаляются. Id профиля выбирает подкаталог `swapforth/<id>/` или `fsys/fasm/<id>/` уже после выбора `sys:`.

Альтернатива — разложить слои SwapForth по каталогам fsys. Отклонено: SwapForth остаётся одним инструментом.

### fasm — буфер на хосте, не словарь цели

Слово `+,` выполняется, пока Gforth читает файл, и кладёт одну команду по `pc`. `alu,` не заводит имя в целевой словарь. `[asm]` обнуляет буфер и `pc`. `[endasm]` печатает строки обёртки: j1a — одна команда на строку, j1b — два полуслова, младшее соответствует чётному `pc`. Сырой файл на 256 байт, как у MC14500, не пишется.

Проверка первого слоя — прогон Gforth этого текста, без `fsoc --build` и без UART. Поток j1a: `8001 8002 4004 0003 6203 608c`. Три слова j1b: `80028001 00034004 608c6203`.

### kernel словами fasm, common текстом ядра

`fsys/kernel/j1a` и `fsys/kernel/j1b` — два текста. Ширина клетки и часть команд расходятся, общего файла нет. Фортовское `@` собирается из двух команд fasm.

`fsys/common` — один файл. Его компилирует `quit` уже запущенного kernel, тем же шагом подачи, которым SwapForth дописывает `swapforth.fs`. `cross.fs` этот файл не читает. Смещение, зависящее от ширины клетки, — слово kernel, не число в общем тексте.

Сессия kernel и common проверяется через `s" fsys" sys:` и `FSOC_EMU_UART_IN`, тем же ожиданием ` ok`, что консоль SwapForth. Отдельного загрузчика для теста не делаем.

### Лампа

`firmware/lamp.fs` дописывается после образа только если шаг инструмента оставил Форт, который принимает файл. Голый `[asm]` подачу не запускает, и лампа в hex не попадает.

### Покрытие

`fcov` запускается по каталогу слоя, не по всему репозиторию. Пять отчётов: два fasm, два kernel, один common. Ниже 90% слой не закрыт. Монолит `swapforth/` в эти отчёты не входит.

## Risks / Trade-offs

- [Перенос `swapforth/` ломает тесты и спеки, пока пути старые] → перенос, префикс `soc-swap`, тесты и дельты путей — одна задача. До неё консоль `soc_emul` собирается из старого каталога.
- [Спецификация `soc` требует полный ANS CORE у любого образа] → дельта сужает это требование до пустого `sys:` и `swapforth`. fsys меряется своей спецификацией.
- [Ядро большое, 90% fcov легко не набрать] → порог в задаче слоя, не в конце изменения. Незакрытые слова дописываются тестами того же слоя.
- [До появления `sys:` сессию kernel нечем запустить] → fasm проверяется на хосте. Поле `sys:` и шаг fsys появляются до задачи kernel. Пока ядра нет, `s" fsys" sys:` останавливается явной фразой и не копирует hex SwapForth.

## Migration Plan

1. Слой fasm и его тесты на хосте. Каталог `swapforth/` и поле `sys:` не двигаются.
2. Перенос монолита, `sys:`, удаление `kit.cross$`, один шаг инструмента вместо прямого `soc-cross`. Проекты без `sys:` по-прежнему дают консоль SwapForth.
3. kernel для j1a и j1b, сессия `words` и `1 2 + .`.
4. common, сессия с `variable` и `/`.
5. `AGENTS.md` и `CHANGELOG.md` в той задаче, которая меняет пути.

Откат — вернуть каталог в `cpu/j1/swapforth/` и убрать `sys:` из манифеста. Образы fsys в проектах без этого поля не используются.
